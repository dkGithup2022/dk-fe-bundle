# fe-extract-data-spec 실행 예시

Peeple(지역 모임 · 이벤트 서비스) 을 이 체인으로 만든 실제 실행에서 발췌했다. 실행일 2026-09-22. v1 에 사람이 직접 피드백을 적고, 그것을 반영해 v2 를 만들었다.

## 입력

- `docs/data-inventory.md`
- 화면 이미지 26장

## 사람이 정한 것

- v1 문서에 직접 적은 피드백: 장소는 지도 API 로 복원 가능한 최소 인자만, 정렬 기준은 없어도 됨, 게시판 대신 이벤트 · 게시글 · 후기가 그 역할 등
- v2 에서 결정: 이벤트 시리즈 없음(정기 등록은 이벤트 N건 생성), 게시글 본문은 마크다운 문자열

## 산출물

### v1 에 사람이 적은 피드백

출처: `docs/data-spec.md`

```markdown

스펙에서 뺀 것 (미결):

- 이벤트 회차: 미결. 지금은 이벤트 한 건 = 날짜 하나로 둠
- 소속 미정 필드 4개: 관심사, 주최자 표시, 최근 기록, 예정 이벤트·새 지원서 수

- 모임 만들기 진행 단계: 저장 여부 미정
```

### v2 의 피드백 반영 요약

출처: `docs/data-spec-v2.md`

```markdown
## v1 피드백 반영 요약

| 피드백 | 반영 |
|---|---|
| 장소는 네이버·카카오 지도 중 하나. 복원 가능한 인자 + 이름만 저장 | `Place` 타입 신설. 모임·이벤트에 `location: Place \| null`. 근거와 API 는 docs/장소전략.md |
| 정렬 기준은 없어도 됨 | 뺌 |
| 이벤트 회차가 따로 있어야 하나 모르겠음 | 결정됨. 시리즈 없음. 정기 등록은 이벤트 레코드를 N개 넣는 것. "정기 모임" 여부는 모임의 플래그 |
| 소속 미정 필드 4개 보류 | 그대로 보류 |
| 모임 만들기 진행 단계는 저장 없어도 됨 | 뺌 |
| 게시판은 이벤트 · 모임 게시글 · 모임 후기가 게시글 역할 | 게시판 항목 없음. 모임 페이지 탭은 이 셋의 목록 |
| 모임 카테고리는 배열, 또는 대표 1 + 소속 배열 | 대표 1 + 소속 배열로 반영 |
| 이야기 → 모임 게시글 | 이름 전부 교체. `GroupArticle` |
| 좋아요 · 댓글은 모임 / 모임 게시글 / 모임 후기 / 이벤트 에 다 달리게 | `targetType` + `targetId` |
| 댓글에 `CommentOrder` 자료형. 스펙은 나중에 | 자리만 둠 |
| 알림에 type, content | 반영 |
| 지원서 상태에 승인 · 거절 | `APPROVED`, `DENIED` 추가 |
| 본문 블록 종류가 의미 불명. 의견 듣고 싶음 | 결정됨. 마크다운 편집기 + 뷰어. `body: string` |
```
