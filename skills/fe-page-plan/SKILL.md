# 페이지 제작 계획

> 산출물(`docs/`, `src/` 아래 파일)은 플러그인 폴더가 아니라 **현재 작업 중인 프로젝트** 아래에 만든다. 스킬 본문의 경로는 모두 그 프로젝트 기준이다.

## 에이전틱 동작

이 동작은 에이전틱한 동작입니다. 아래 순서에 맞게 실행하되, 수행 계획과 종료 조건을 고려하여 여러 번 수행해 결과를 도출해도 됩니다.

### 목적

실제 페이지를 만들기 전에 사람이 검사할 수 있는 계획서와 와이어프레임을 내놓는 것이 목적입니다. 계획서는 세 가지를 보여줍니다. 핸드오프 문서끼리 충돌하는 곳, 화면에서 값을 읽지 못해 정하지 않은 UI 세부(마진 · 패딩 · 크기), 그 밖에 제작에 필요한 판단. 와이어프레임은 디자인이 온전히 입혀지지 않은 구조 확인용 UI 입니다. 허가가 나기 전에는 실제 라우트를 만들지 않습니다.

### 입력 & 출력

입력:
- `docs/pages/{라우트 이름}/data.md` (fe-page-data 산출물)
- `docs/pages/{라우트 이름}/components.md` (fe-page-components 산출물)
- `docs/pages/{라우트 이름}/api.md` (fe-page-api 산출물). 동작 표의 "부르는 것" 은 여기서 가져온다
- 페이지 디자인. 그 페이지에 속하는 화면 이미지 파일들. 인자로 받거나 대화에서 추론한다.
- `src/` 의 현재 상태: 타입, 컴포넌트, `src/lib/api/mock/handlers.ts`, `src/lib/*-api.ts`
- 대화에서 사용자가 정한 사항.

출력:
- `docs/pages/{라우트 이름}/plan.md`: 제작 계획서. 아래 형식.
- `src/app/dev/wireframe/{라우트 이름}/page.tsx`: 와이어프레임. 개발 전용 라우트. 있는 컴포넌트를 그대로 쓰고, 없는 컴포넌트와 정하지 않은 곳은 회색 상자와 글자로 자리만 잡는다. 데이터는 화면 문구를 그대로 넣은 상수. production 에서는 `notFound()`. 실제 페이지가 만들어지면 지운다.
- 와이어프레임 스크린샷. 계획서에 경로를 적는다.

```markdown
# {라우트 이름} 제작 계획

라우트: /{route}
화면: {파일명}, {파일명}
입력: docs/pages/{라우트 이름}/data.md, docs/pages/{라우트 이름}/components.md, docs/pages/{라우트 이름}/api.md
작성: {날짜}
상태: 검사 대기. 사용자가 "허가" 로 바꾸면 fe-page-build 를 실행한다.

## 1. 충돌 검사

핸드오프 문서끼리, 그리고 문서와 화면 사이에 어긋나는 곳. 없으면 "없음".

| # | 어디와 어디 | 내용 | 제안 |
|---|---|---|---|
| 1 | components.md {컴포넌트} props ↔ data.md | {컴포넌트가 받는 필드가 data.md 에 없음} | {어느 쪽을 고칠지} |
| 1b | api.md 응답 ↔ data.md · components.md | {응답 필드가 컴포넌트가 받는 것과 다름} | |
| 2 | data.md ↔ 화면 | {화면에 있는데 data.md 에 없음} | |
| 3 | components.md ↔ src/components | {문서의 컴포넌트가 코드에 없음 / props 가 다름} | |

## 2. 구조

파일:
- src/app/{route}/page.tsx — 서버. metadata: title "{제목}", description "{설명}"
- src/app/{route}/{Name}Client.tsx — 본문. 상태와 이벤트
- src/app/{route}/loading.tsx — 스켈레톤. 본문과 같은 max-w

영역과 컴포넌트 (components.md 의 순서대로):
```
{Name}Client
├── A {영역}: {컴포넌트} ({props 요약})
├── B {영역}: {컴포넌트}
│   └── {하위 컴포넌트} × n
└── ...
```

상태:

| 이름 | 타입 | 초기값 | 어디서 바뀜 |
|---|---|---|---|
| {state} | {타입} | {값} | {동작} |

동작:

| 동작 | 트리거 | 결과 | 부르는 것 |
|---|---|---|---|
| {무엇} | {버튼 · 진입 · 탭} | {상태 변화 · 이동} | {lib/{domain}-api.ts {함수} / 없음} |

## 3. 정하지 않은 UI 세부

화면에서 값을 읽지 못한 것. 와이어프레임에는 가정값으로 그렸다. 검사에서 정해 주면 그 값으로 만든다.

| 영역 | 항목 | 가정값 | 근거 · 이유 |
|---|---|---|---|
| {A} | {카드 사이 간격} | {12px} | {화면에서 눈대중} |
| {B} | {빈 상태} | {EmptyState "{문구}"} | {화면에 없음} |

## 4. 제작에 필요한 판단

| 항목 | 판단 | 이유 |
|---|---|---|
| API | api.md 의 항목이 전부 "있음" 인지 확인. "새로 필요" 가 남아 있으면 fe-generate-api 를 먼저 돌린다 | api.md |
| 인증 | {필요한 동작과 비로그인일 때 처리} | |
| 이동 | {누르면 어디로. 라우트가 아직 없으면 "미정"} | |
| 스켈레톤 | {영역별 상자 수} | |
| 그 외 | | |

## 5. 와이어프레임

- 라우트: /dev/wireframe/{라우트 이름}
- 스크린샷: {경로}
- 그린 것: {있는 컴포넌트로 그린 영역}
- 자리만 잡은 것: {회색 상자로 둔 영역과 이유}
```

### 권장 동작 순서

1. 핸드오프 읽기
   `data.md` · `components.md` · `api.md` 를 읽고 화면 이미지를 본다. `src/` 에서 문서가 가리키는 타입 · 컴포넌트 · API 함수가 실제로 있는지 확인한다.

2. 충돌 검사
   네 방향으로 대조한다. components.md 의 props ↔ data.md 의 필드. api.md 의 응답 ↔ data.md · components.md. 문서 ↔ 화면. 문서 ↔ src/. 어긋난 곳은 제안과 함께 적는다. 스스로 고치지 않는다.

3. 구조 · 상태 · 동작 적기
   components.md 의 영역 순서대로 컴포넌트 트리를 그린다. 상태는 useState 를 기본으로 하고, 여러 페이지가 공유하거나 새로고침 후 남아야 하는 것만 store 로 표시한다. 동작마다 부르는 API 를 api.md 에서 가져와 적는다. api.md 에 없는 동작이 나오면 충돌로 올린다.

4. 정하지 않은 UI 세부 모으기
   마진 · 패딩 · 간격 · 크기 · 빈 상태 · 로딩 · 에러 중 화면에서 읽지 못한 것을 가정값과 함께 적는다.
   전체 컨테이너와 각 하위 컴포넌트와 구성 요소는 고정 크기보다는 flex 를 사용하는 것이 권장됩니다. 크기를 직접 선언해야 한다면 숫자를 넣기 보다는 tailwind 변수에 제안된 크기 숫자가 있는지 확인하세요. 가정값도 그 기준으로 적는다.

5. 와이어프레임 만들기
   `src/app/dev/wireframe/{라우트 이름}/page.tsx` 를 만든다. 있는 컴포넌트는 그대로, 없는 컴포넌트와 4단계의 항목은 회색 상자 + 이름표. 데이터는 화면 문구를 상수로. 개발 서버로 띄워 스크린샷을 찍는다.

6. 계획서 쓰기
   `docs/pages/{라우트 이름}/plan.md` 로 쓴다. 스크린샷 경로를 넣는다.

7. 검사 요청
   계획서와 스크린샷을 보여준다. 충돌과 판단 항목 중 갈리는 것은 AskUser 로 묻는다. 허가는 사용자가 준다. 이 스킬은 여기서 멈춘다.

### 종료 조건

- [ ] 충돌 검사가 네 방향 모두 되어 있고, 항목마다 제안이 있다
- [ ] 구조 · 상태 · 동작 표가 있고, 동작마다 부르는 함수 또는 "없음" 이 적혀 있다
- [ ] 와이어프레임 라우트가 뜨고 스크린샷이 계획서에 있다
- [ ] `docs/pages/{라우트 이름}/plan.md` 가 "검사 대기" 상태로 저장되었다

아래 상황이면 AskUser 로 상황을 브리핑하고 정보를 구하세요.
- 핸드오프 문서끼리 충돌해 어느 쪽이 맞는지 정할 수 없다
- 동작의 결과가 화면에 없다 (제출 후 어디로 가는지 알 수 없다)
- 이동할 라우트가 아직 없다
- 인증이 필요한 동작인데 비로그인 처리가 화면에 없다
