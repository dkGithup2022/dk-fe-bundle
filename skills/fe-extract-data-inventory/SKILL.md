# 데이터 목록 추출

> 산출물(`docs/`, `src/` 아래 파일)은 플러그인 폴더가 아니라 **현재 작업 중인 프로젝트** 아래에 만든다. 스킬 본문의 경로는 모두 그 프로젝트 기준이다.

## 에이전틱 동작

이 동작은 에이전틱한 동작입니다. 아래 순서에 맞게 실행하되, 수행 계획과 종료 조건을 고려하여 여러 번 수행해 결과를 도출해도 됩니다.

### 목적

화면 전체를 보고 이 서비스가 다루는 데이터를 두 종류로 나눠 이름과 한 줄 설명으로 목록화하는 것이 목적입니다. 물리적인 테이블 구조는 생각하지 않습니다. 필드와 값은 다음 스킬(fe-extract-data-spec)이 맡습니다.

### 입력 & 출력

입력:
- 화면 이미지 폴더. 인자로 받거나 대화에서 추론한다.
- 디자인 핸드오프에 용어 목록이 있으면 도메인 이름은 그 용어를 쓴다.
- 대화에서 사용자가 정한 사항 (확정 화면안, 제외할 화면).

출력:
- `docs/data-inventory.md`. 아래 형식.

```markdown
# 데이터 목록

작성: {날짜}

## 화면

폴더에 있는 파일명을 그대로 적는다. 폴더 위치는 적지 않는다.

- {파일명}: {화면 한 줄 요약}
- {파일명}: {화면 한 줄 요약}

## 논리적 도메인

- {도메인 이름}: {1줄 설명}
- {도메인 이름}: {1줄 설명}

## 기능 데이터

- {기능 데이터 이름}: {1줄 설명} — {나오는 화면 파일명}, {파일명}
- {기능 데이터 이름}: {1줄 설명} — {파일명}

## 애매한 것 (사용자 판단 필요)

도메인인지 기능 데이터인지 가르기 어려운 것. 도메인 후보도 확신이 없으면 여기에 둔다.

- {이름}: {1줄 설명} — {파일명}. 후보: {도메인 | 기능 데이터}, 이유: {한 줄}

## 소속 미정 필드 (사용자 판단 필요)

화면에 있지만 어느 항목의 필드인지 정하기 어려운 것.

- {필드 이름}: {화면에 보이는 문구} — {파일명}. 후보: {항목 A} 또는 {항목 B}
```

### 구분 규칙

DDD 에서의 논리적 도메인 데이터가 될 수 있는 것과, 단순 기능을 지원하기 위한 데이터를 분류하여 나열합니다.
아래는 참고용 규칙이지만, 기계적으로 따를 필요는 없습니다.
아래 규칙에 위배되어도, 논리적 데이터로 승격이 필요하다면 제시해 주세요.

1. 독립적인 의미를 가지며 도메인으로 관리되어야 하는 데이터인가?
   예: 상품, 유저, 배송, 알림, 팔로우, 아티클.
   → 논리적 도메인
   확신이 없는 도메인 후보는 여기에 넣지 말고 "애매한 것" 에 둔다.

2. 정해진 값 중에서 고르거나 표시하는 것인가?
   칩, 라디오, 탭, 배지 문구, 상태 문구처럼 값의 나열이다.
   → 기능 데이터 (enum)

3. 단순 유즈케이스의 분기이거나, 유즈케이스를 지원하기 위한 기능인가?
   예: 자동 저장, 진행 단계, 안내에 응답했는지.
   → 기능 데이터 (저장)

4. 위 어느 것도 아닌가?
   다른 데이터에서 계산되는 값(남은 수량, 상대 시간), 안내 문구, 글자 수 제한 같은 설정값.
   → 목록에 올리지 않는다. 필요하면 스펙 단계에서 어느 항목의 필드로 흡수한다

판단이 갈리면 "애매한 것" 에, 어느 항목에 속하는지 모르는 필드는 "소속 미정 필드" 에 올린다. 이 두 절은 사용자가 이 단계에서 직접 정한다.

### 권장 동작 순서

1. 화면 읽기
   폴더의 이미지를 전부 본다. 화면마다 파일명과 한 줄 요약을 적는다. 같은 화면의 안이 여러 개면 어느 것이 확정인지 화면 안의 표시로 판단하고, 표시가 없으면 사용자에게 묻는다.

2. 목록 뽑기
   구분 규칙에 따라 논리적 도메인과 기능 데이터로 나눈다. 항목마다 이름과 한 줄 설명을 적고, 기능 데이터는 나오는 화면 파일명을 붙인다. 가르기 어려운 것은 "애매한 것" 에, 어디에 속하는지 모르는 필드는 "소속 미정 필드" 에 후보와 이유를 적는다. 억지로 결정하지 않는다.

3. 사용자 확인
   네 절을 보여준다. 사용자가 이 자리에서 정한 것은 반영하고, 정하지 않은 것은 그대로 둔다.

4. 파일 쓰기
   `docs/data-inventory.md` 로 쓴다. 화면은 파일명만 적고 경로는 적지 않는다. 남은 애매한 것과 소속 미정 필드는 그대로 남겨 다음 스킬에서 다시 묻게 한다.

### 종료 조건

- [ ] 화면에 보이는 데이터가 전부 도메인 · 기능 데이터 · 애매한 것 · 소속 미정 필드 중 한 곳에 있다
- [ ] `docs/data-inventory.md` 가 위 형식으로 저장되었다
