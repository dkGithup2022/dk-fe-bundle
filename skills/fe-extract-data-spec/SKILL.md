# 데이터 스펙 추출

> 산출물(`docs/`, `src/` 아래 파일)은 플러그인 폴더가 아니라 **현재 작업 중인 프로젝트** 아래에 만든다. 스킬 본문의 경로는 모두 그 프로젝트 기준이다.

## 에이전틱 동작

이 동작은 에이전틱한 동작입니다. 아래 순서에 맞게 실행하되, 수행 계획과 종료 조건을 고려하여 여러 번 수행해 결과를 도출해도 됩니다.

### 목적

목록에 오른 도메인과 기능 데이터마다 화면에 근거한 필드와 값을 정해 문서로 남기는 것이 목적입니다. 물리적인 테이블 구조는 생각하지 않습니다. 코드 파일은 만들지 않습니다. 사용자가 문서를 직접 고친 뒤 다음 스킬이 코드로 옮깁니다.

### 입력 & 출력

입력:
- `docs/data-inventory.md` (fe-extract-data-inventory 산출물). 없으면 그 스킬을 먼저 실행한다.
- 화면 이미지 폴더. 인자로 받거나 대화에서 추론한다. 목록의 파일명을 이 폴더에서 찾는다.
- BE 핸드오프의 데이터 스펙 (있으면). 있으면 필드명과 값은 BE 를 따른다.
- 대화에서 사용자가 정한 사항.

출력:
- `docs/data-spec.md`. 아래 형식. 이미 있으면 `docs/data-spec-v{n}.md` 로 새 판을 만든다.

```markdown
# 데이터 스펙

작성: {날짜}
입력: docs/data-inventory.md, 화면 이미지 {n}장
상태: 사용자 검수 전. 이 파일을 직접 고친 뒤 fe-generate-data-types 를 실행한다.

## 결정 필요

스펙을 정하다 갈린 것. 항목마다 후보와 근거를 적고 사용자에게 맡긴다.

### {주제}
{화면 근거}. 후보 A: {…}. 후보 B: {…}. 의견: {…}

## 보류

이번 스펙에서 뺀 것과 이유.

- {이름}: {이유}

---

## 도메인

### {항목 이름}
{1줄 설명} — {근거 화면 파일명}, {파일명}

| 필드 | 타입 | 필수 | 근거 |
|---|---|---|---|
| id | number | 예 | 관계 표현용 |
| {필드} | {타입} | {예 / 아니오} | {파일명} "{화면에 보이는 문구}" |
| {필드} | {타입} \| null | 예 | {파일명} "{문구}". null 이면 {뜻} |

관계: {항목} → {항목} ({참조 필드}).

## 값 타입

도메인의 필드에 들어가지만 독립 저장은 없는 것.

### {이름}
{1줄 설명} — {근거}

| 필드 | 타입 | 필수 |
|---|---|---|

## 기능 데이터 (enum)

값은 SCREAMING_SNAKE_CASE, 라벨은 화면 문구 그대로.

### {EnumName} — {파일명}
- 쓰는 곳: {도메인 이름}.{필드} | {기능 이름} 화면 분기

| 값 | 라벨 |
|---|---|
| {VALUE_A} | {화면 문구} |
| {VALUE_B} | {화면 문구} |

## 기능 데이터 (저장)

### {이름} — {파일명}
- 저장 단위: {사용자별 / 전역}. 기능 이름: {기능 이름}

| 필드 | 타입 | 필수 | 근거 |
|---|---|---|---|
```

### 권장 동작 순서

1. 목록 읽기
   `docs/data-inventory.md` 의 항목과 근거 화면 파일명을 뽑고, 이미지 폴더에 그 파일이 있는지 확인한다. "애매한 것" 과 "소속 미정 필드" 가 남아 있으면 억지로 정하지 않는다. 사용자가 이 자리에서 정하면 반영하고, 아니면 "결정 필요" 나 "보류" 로 옮긴다.

2. 항목마다 화면 다시 보기
   근거 화면 이미지를 열어 그 항목에 속하는 정보를 전부 적는다. 표시용으로 가공된 값(상대 시간, 남은 수량 같은 계산 결과)은 원본 값(ISO 날짜, 원래 수치)으로 되돌린다.

3. 스펙 표 만들기
   - 도메인: 필드 · 타입 · 필수 · 근거 화면과 표시 문구. 화면에 근거 없는 필드는 넣지 않는다. id 는 관계 표현용으로만 둔다.
   - 값 타입: 여러 도메인의 필드에 같은 모양으로 들어가는 것.
   - enum: 값 · 라벨. "쓰는 곳" 에 어느 도메인의 어느 필드인지, 또는 어느 기능의 화면 분기인지 적는다. 다음 스킬이 이것으로 파일 위치를 정한다.
   - 기능 저장 데이터: 저장 단위와 기능 이름.
   - 관계는 id 참조로 적는다. 화면이 두 항목을 한 덩어리로 같이 보여주는 경우만 중첩으로.
   - BE 스펙이 있으면 이름과 값을 BE 에 맞추고 표에 "BE" 라고 표시한다.
   - 정하기 어려운 것은 "결정 필요" 에 후보와 의견을 적는다.

4. 파일 쓰기
   `docs/data-spec.md` 로 쓴다. 사용자에게 "이 파일을 고친 뒤 fe-generate-data-types 를 실행" 하라고 알린다.

### 종료 조건

- [ ] 목록의 모든 항목이 스펙 표에 있거나 "보류" 에 이유와 함께 있다
- [ ] 모든 필드와 enum 값에 근거 화면이 적혀 있고, enum 마다 "쓰는 곳" 이 있다
- [ ] `docs/data-spec.md` 가 위 형식으로 저장되었다

아래 상황이면 AskUser 로 상황을 브리핑하고 정보를 구하세요.
- 같은 정보가 화면마다 다른 이름이나 다른 형식으로 나온다
- BE 스펙과 화면이 충돌한다
- 목록에는 있는데 근거 화면에서 필드를 하나도 찾지 못했다
- 목록에 적힌 화면 파일이 이미지 폴더에 없다
